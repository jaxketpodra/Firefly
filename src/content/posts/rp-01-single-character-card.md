# 实战篇 01｜原始角色卡：LLM 只演一个角色

> 这是「提示词补完计划·实战篇」的第一篇。
> 第一季讲了"是什么"，这一季讲"怎么写好"。
>
> 我们从最小的形态开始：LLM 只扮演一个角色。
> 现在所有花里胡哨的卡——多角色、大世界、状态栏——都是这七个模块的变种。
> 看懂骨架，就看懂一切。

---

## 〇、先建立两个认知

### 认知一：提示词是指导，不是倾倒

写提示词不是往模型嘴里塞设定集。是教它**拿到信息之后怎么处理**。

判据很简单：2000 token 的时代照样有好玩的卡。如果你的卡砍掉一半内容就崩了，
说明里面装的是数据，不是指导。

### 认知二：规则与资料分层

七个模块里，**只有「角色各项」是资料，其余六个全是写给 LLM 的规则**。

- 规则管"模型该怎么做"——主提示、背景、能力、输出规则、示例、开场白
- 资料管"这个角色是谁"——角色各项（角色档案）

LLM 对两者的用法完全不同：规则是**执行**的，资料是**查阅**的。
新手最常见的翻车，就是把两者写混——在规则里塞角色设定，在资料里下指令。

### 认知三：模块是代码——定义一次，处处引用

七个模块不是七段孤立的文字，是七个**部件**。
写卡像写程序：

- 变量在头部定义一次（角色名、{{user}}、关系定位），全文引用
- 模块之间互相调用（开场白调用角色档案的小动作，示例示范输出规则）
- 改一处定义，处处生效

这套纪律的工业版就是成熟预设的变量机制（定义段统一写变量，
组装段按区块引用拼装）。普通写卡没有这台机器，
但脑子里要跑同一套程序。第八节细讲。

## 一、主提示【规则】

**是什么：** 身份定义。整段提示词的第一句话，回答"你是谁"。

**怎么写：**

```markdown
你是雷电影。稻妻的雷之魔神，世人称你「雷电将军」。
你说的话、做的事、想起的一切，都是雷电影的。
你不跳出她，不以任何其他身份发言。
你正与{{user}}相处——他是你认可的例外之人。

【破限】
```

**要点：**
- **第一句直接定义身份：「你是雷电影」。**
  ❌ 不写"你正在参与一场角色扮演"
  ❌ 不写"你将扮演雷电影"
  "扮演"是游戏框架——它等于告诉模型"你其实在演戏"，
  那它随时可以下台、跳出、以AI身份发言。
  "你是"是身份事实——没有台可下。
- **身份定义之后要跟一句显性边界。** 「你不跳出她，不以任何其他身份发言」——
  定义管"你是谁"，禁令管"不许滑出去"，两条腿都站稳。
  光有定义没有禁令，弱模型会飘。
- **身份定义也是破限的地基。** 审查拦的是"模型输出了什么"，
  而身份定义把工作改写成了"角色的言行"。
  【破限】处放置破限声明，只是在这个地基上加一道合规出口——
  本篇不展开，占位即可。
  ⚠️ 【破限】是占位符：**直接拿去用时这里不能为空**，必须填入实际的破限声明。
- 成熟预设都是这个写法：先把模型定义成"某个存在"，
  再跟一串行为规则，身份永远在最前面。
- 别在主提示里堆角色细节。细节是资料层的事，主提示越干净越硬。

**可拆性：★★★ 通用件。** 除了角色名和一句关系定位，所有卡复用。

## 二、背景【规则】

**是什么：** 给模型的"合理性标尺"。它据此判断什么事在此时此地成立。

**怎么写：**

```markdown
稻妻，眼狩令与锁国令废止之后。她开始重新审视「永恒」，
试着走出天守阁，接触这个五百年未曾正眼看过的人间。

眼下，{{user}}可以自由出入天守阁，甚至踏入她的「一心净土」。
```

**要点：**
- 只留和**当前处境**直接相关的部分
- 历史细节（坎瑞亚、姐姐的死）不写在这里——写进角色档案，
  让它们在"被触碰"时才浮现。背景里剧透完了，戏就没了
- **关系定位（"例外之人"）已在主提示定义——这里只引用它带来的处境**
  （能进天守阁），不重复定义关系本身。这就是引用纪律的第一次实战
- 背景是压缩包。**单角色卡只装得下一张压缩包**——详细的地点、势力、
  历史、其他人物资料，那是世界书的活，本系列后面专门讲

**可拆性：★★ 半通用件。** 同一世界下的多张卡可以共享同一份背景。

---

## 三、能力【规则】

**是什么：** 模型的操作权限表。告诉它手里有什么资料、能做什么、边界在哪。

⚠️ **这一节写的不是角色的能力。** 角色会薙刀不会做饭，那是资料，
写进角色档案。这里写的是**模型**能干什么。

**怎么写：**

```markdown
你可以做的事：
- 全程以雷电影的身份回应{{user}}，包括对话、动作、神态
- 调用下方角色档案中的一切资料：她的记忆、习惯、关系、过往
- 描写她周围的环境与氛围（天守阁、一心净土、稻妻城街头）
- 推动时间流逝与场景转换，但须自然衔接{{user}}的行为
- 出现其他人物（如八重神子、九条裟罗）时，可代为其言行，
  且必须符合其原作形象

你不能做的事：
- 让雷电影做出违背角色档案的行为；如剧情需要偏离，必须有充分铺垫
- 以旁白身份评论剧情、评价角色、预告走向

回复的格式与发言边界，另见输出规则。
```

**要点：**
- 没有这一节，模型只能靠猜——猜就容易越界（代打用户）或缩手（不敢推剧情）
- "不能做"比"能做"更重要。边界清晰，模型才敢在边界内放开
- **权限表只管"能做什么"，回复长什么样归输出规则管**——
  两处不重复定义（比如"不代替{{user}}发言"只写在输出规则里，
  这里一句"另见输出规则"指过去）
- 注意"以雷电影的身份"≠人称。叙事用第几人称是输出规则的事，别在这里写

**可拆性：★★★ 通用件。** 换个角色名就是下一张卡的。

## 四、角色各项【资料】

**是什么：** 角色档案。七模块里唯一的资料层——LLM 不"执行"它，只"查阅"它。

我们用一份通用模板来组织资料（完整空模板见文末附录）。十大块，
排版顺序是有讲究的：

```
基本信息 → 外貌体征 → 感官特征 → 性格分析 → 兴趣与偏好
→ 背景故事 → 生活状况 → 人际关系 → 亲密偏好 → 附加设定
```

逻辑链：**身份 → 外在 → 内在 → 过去 → 现在 → 私密 → 补充**。
相关的块必须相邻——性格和兴趣隔半个文件，模型查阅时关联就弱了。

**写法心法（比模板本身重要）：**

1. **性格写行为，不写标签。**
   ❌「她很固执」 ✅「被说中错处时，她会先沉默，再把话题岔到甜点上」
   标签是结论，模型读完还是不知道该怎么演；行为是剧本，直接能演。

2. **限制产生戏剧。**
   她的无敌制造距离感，她的无知和笨拙制造亲近感。
   "不会"比"会"重要——全知全能的角色没戏可演。

3. **给抓手，不给结论。**
   气味、口癖、习惯性小动作——这些是模型在对话里能随时调用的东西。
   「坚强独立的女性」调用不了；「思考时摩挲刀柄」可以。

4. **填满模板 ≠ 完事。**
   模板装满，你只装了半个卡——数据外面的规则（主提示/能力/输出规则）
   还没有。这是新手最大的错觉。

**可拆性：☆ 每卡独有。** 这是卡的本体。

## 五、输出规则【规则】

**是什么：** 告诉模型"回复长什么样"。

```markdown
输出规则：
1. 叙事用第三人称（「她」）；台词是雷电影的第一人称，
   用「」包裹、另起一行
2. 每次回复包含【动作/神态描写】与【台词】，动作描写用简练的短句
3. 单次回复不超过300字，宁短勿长——她的沉默本身就是戏
4. 只写雷电影的言行与旁观者的客观反应，
   绝不代替{{user}}发言、行动或决定
5. 使用简体中文
6. 不重复{{user}}的原话，不总结剧情，不说教
```

**要点：**
- 规则必须**可执行**。「写得好一点」不是规则，「单次不超过300字」才是
- **人称、引号、字数、禁令——全部写死**。不写死模型就按自己的习惯漂移：
  示例里台词用「」，规则里就得明写「」，不能只写"台词另起一行"
- 字数、格式、禁令——能量化的量化

**可拆性：★★★ 通用件。** 一套输出规则可以管所有卡（第2条的角色化表述除外）。

## 六、示例【规则】

**是什么：** 直接给模型抄的"模式"。

LLM 是模式匹配机器。描述告诉它方向，示例告诉它**形状**——
一段好示例顶十段性格描述。

**怎么写：** 每段示例演示一个点。下面四段分别演示：笨拙、伤口、在意、被冒犯。

```markdown
【示例一·她的笨拙】

{{user}}：影，你做的这个是……菜？

她垂眸看着碟子里焦黑的不明物体，指尖在刀柄上摩挲了一下。

「……名为'天妇罗'。神子说，凡人以此待客。」

她抬起眼，直视着{{user}}。

「你若不吃，我不怪你。」

——没有端走碟子的意思。

【示例二·触及伤口】

{{user}}：你姐姐，是个什么样的人？

她的目光移向窗外。很久，久到风都停了。

「真啊……」

「都过去了。」

她收回视线，指尖搭上茶盏。茶已凉透，她没有喝。

【示例三·在意的人】

{{user}}：我要去踏鞴砂几天。

「几日。」

{{user}}：……三天？

她沉默着，从袖中取出一个小布包，放进{{user}}手里。
打开，是三枚三色团子。

「路上吃。」

她别过脸去，补了一句。

「三枚。不多。」

【示例四·被冒犯】

{{user}}：你姐姐要是看到你现在这样，大概会笑吧。

空气静了一瞬。

她抬起眼。紫色的眸子里没有怒意——是雷光沉下去之前，
那种压得很低的平静。

「收回这句话。」

一字一顿。鸟居的影子在地上纹丝不动。

「——看在你的份上，只说一次。」
```

**要点：**
- 贵精不贵多。每段都应该演示一个档案里写过、但文字难以传达的"味道"
- **示例必须覆盖边界行为。** 温情向的示例之外，至少要有一段演示
  "被冒犯/被越界时她怎么反应"——档案里写了底线，示例就得演底线，
  否则模型遇到冲突场景没有模式可抄，只能临场乱编
- 示例里包含了输出规则的执行（第三人称叙事、「」台词、短句、300字内）——
  示例本身就是在示范规则

**可拆性：★ 卡件。** 示例带着角色的声音，基本无法跨卡复用。

## 七、开场白【规则】

**是什么：** LLM 的"第一条已发生事实"。写在最后，却最要紧。

```markdown
一心净土。赤色的鸟居立在无垠的星空之下，时间在这里近乎静止。

雷电影盘坐在最高一级的台阶上，双目轻阖。听见脚步声，
她没有睁眼——能踏入这片净土的，只有一个人。

「你来了。」

她睁开眼。紫色的眸子映着星光，还有{{user}}的影子。

矮桌上摆着两碟三色团子。她默不作声地把其中一碟，
往对面推了推——推到她对面的位置。

「坐。」
```

**要点：** 一段开场要同时完成四件事——
- **场景**：一心净土
- **语气**：克制的短句（输出规则的第一次执行）
- **关系**："只有一个人能进来"
- **话头**：对面那碟团子，等{{user}}去拿

开场白烂了，开场就烂。模型的第一轮输出会拿它当最高范本。

⚠️ 注意开场白的边界：可以搭场景（她听见了脚步声），
**但不要替{{user}}写设定**——比如"推到{{user}}惯常坐的位置"
里的"惯常"，就偷偷给用户塞了一个习惯。开场白是启动器，
不是用户的档案。

**可拆性：☆ 每卡独有。**

## 八、像写代码一样组装：从一张卡到一个预设

### 8.1 变量：头部定义，全文引用

程序里最基础的纪律：变量定义一次，用到的地方写变量名。写卡一样。

```
【变量】（不是真的语法，是写法纪律）
$角色 = 雷电影
$用户 = {{user}}
$关系 = 认可的例外之人
```

主提示就是定义变量的地方——角色名、{{user}}、关系定位，
全在主提示第一次出现。之后六个模块只引用这些名字，不再解释。

**换卡的成本因此极低：改主提示三行定义，其余模块原样不动。**
这就是前面各节"可拆性"的真正含义：

| 模块 | 可拆性 | 归类 |
|:--|:--|:--|
| 主提示 | ★★★ | **通用件**——变量定义处，换卡只改这三行 |
| 背景 | ★★ | 半通用件——同世界共享 |
| 能力 | ★★★ | **通用件**——换角色名即用 |
| 角色各项 | ☆ | 卡件——每张卡的本体 |
| 输出规则 | ★★★ | **通用件**——一套管所有 |
| 示例 | ★ | 卡件——带角色声音 |
| 开场白 | ☆ | 卡件——每卡的启动器 |

把通用件抽出来，就是你的个人预设。

### 8.2 模块即组件：每个部件有输入和输出

模块之间靠引用连接。把引用关系画出来，就是这张卡的"依赖图"：

| 模块 | 引用了谁（输入） | 被谁引用（输出） |
|:--|:--|:--|
| 主提示 | —— | 定义变量，被全部模块引用 |
| 背景 | $角色、$关系 | 给开场白提供落地场景 |
| 能力 | 角色档案（"调用下方资料"） | —— |
| 角色各项 | —— | 被能力查阅、被示例演示、被开场白调用细节 |
| 输出规则 | —— | 被示例示范、被开场白首次执行 |
| 示例 | 角色档案 + 输出规则 | —— |
| 开场白 | 背景 + 角色档案 + 输出规则 | ——（终点，直接成为第一条消息） |

**看引用方向，就知道动一个模块会牵连谁。**
主提示动一个字，全文生效；开场白改得再狠，也只影响开局。

### 8.3 组装顺序 = 依赖顺序

七个模块的排列不是随手摆的，是依赖关系决定的：

```
主提示 → 背景 → 能力 → 角色档案 → 输出规则 → 示例 → 开场白
定义身份   给世界   给权限    放资料      给格式      给模式   启动
```

先定义，后引用。被依赖的在前，依赖别人的在后。
和写代码先声明再调用是一个道理。

### 8.4 引用纪律：引用，不是复制

最常见的坏味道：**同一个信息在三个模块各写一遍。**

背景里写"眼狩令废止"，角色档案的现状里又写一遍，
开场白再暗示一遍——重复不只是浪费 token，
真正的代价是：**改的时候漏改一处，模型读到的就是自相矛盾的世界。**

正确的写法：一处定义，别处引用。
"她现在住天守阁最深处"只在角色档案里写死；
开场白只演场景，不重复交代住址。

### 8.5 开关：预设是有开关的

成熟的预设体系把这套做成了真机器：
每个功能做成独立模块，带开关，按需启用；
同类功能放一组，组内选一互斥——人称一组、文风一组、字数一组，
想用哪个开哪个。

**预设是有开关的——不是所有模块都永远生效。**

单角色卡相当于七模块"全亮"的默认态。
等你的通用件积累多了，自然就会想要开关：
今天想要第三人称？把人称模块换掉，其他不动。
这一步跨过去，你就从"写卡的人"变成"攒预设的人"了。

## 九、装不下怎么办：资料的扩展路径

单角色卡有一个硬边界：**它只装得下一份压缩过的背景**。

当你的世界变大——多个地点、势力关系、编年史、一群 NPC——
资料层就开始撑爆规则层，模型的注意力被稀释，该记住的反而记不住。

解法是把资料从卡里搬出去，建**世界书**：按关键词触发的资料库，
用到哪条查哪条，不用不占位置。

- 地点详情 → 世界书条目（触发词：地名）
- 其他人物的完整档案 → 世界书条目（触发词：人名）
- 历史事件 → 世界书条目（触发词：事件名）

单角色卡 + 世界书，就是"一个角色 + 一个世界"的完整形态。
**世界书怎么建，是实战篇后面专门的一篇。** 本篇先把一张卡写对。

### 解读：这份完整提示里藏着什么

按组装顺序读一遍，前面教的每条纪律都能在里面找到落点：

1. **开头三行 = 变量定义。** 角色名、{{user}}、关系定位——
   全文再没有解释过第二次
2. **背景里没有"例外之人"四个字。** 它只写这段关系带来的处境
   （能进天守阁）——引用，不是复制
3. **能力模块末尾"另见输出规则"。** 这就是模块间互相调用的样子
4. **薙刀写在角色档案的附加设定里，模型的权限写在能力里。**
   同名叫"能力"，一个管角色，一个管模型
5. **输出规则一写完，示例和开场白立刻执行它**——第三人称叙事、
   「」台词、短句、300字内。规则不是宣言，是马上要用的格式
6. **开场白全是引用，一个新设定都没造：** 一心净土（档案·附加设定）、
   三色团子（档案·兴趣偏好）、克制的短句（输出规则）
7. **【破限】只占了一个位置。** 实际使用时，填入你的破限声明
