## 先解剖一个真预设：狐神抚 V19.3

不空谈。这是我手里一份真实预设的结构——**62 个提示词块**，长这样：

```text
初始化(不要关)                    ← 一串 setvar，清空全部变量
----⚠️声明(必看!)————           ← 分隔符，没有内容，纯视觉分组
🦊狐策~(行动选项)                ← 712 字
🏷️正文<content>标签              ← 146 字
----🚫🔓破限提示词————
普通破限(严格破限在下面)           ← 536 字
----🔁是否转述————
🔁分段转述（选一）                ← 770 字
----🙋抢话要求————
❌禁止抢话（选一）                ← 563 字
----❤️NSFW发情(全部关掉为默认)————
----📝文风要求(选一)————
📝文风|真实感                    ← 741 字
----🗣️对白量(选一)————
----👁️人称要求————
🧍第二人称（选一）                ← 225 字
👁️🔒防全知/防剧透                ← 604 字
💭👤内心OS(只角色)(选一)          ← 190 字
🎞️思维链（多角色内心OS）          ← 3288 字
……共 62 块
```

看出来了吗——**预设不是一段话，是一套模块化的开关系统**：

1. 每个功能是一个独立块，可以单独开关
2. `----标题----` 是分组标记，组内"选一"互斥（文风选了真实感就别再选电影感）
3. 每个块把内容写进一个变量（`setvar`），最后由主提示词按顺序把变量组装起来（`getvar`）
4. 所有块都带注入位置参数——这份预设几乎全部注入在**倒数第 4 条消息**处（depth=4），也就是紧贴最新对话的"高注意力区"（第 02 篇讲的注意力规律的实际运用）

**所以预设到底是什么？** 一句话：

> 预设 = 一套**可开关的系统提示模块库** + **组装顺序** + **注入位置** + 采样参数。

它定义的是"这场戏怎么演"的全部规则：扮演契约、破限声明、文风要求、人称视角、抢话禁令、防剧透、思维链、输出格式、字数档位……唯独不定义"演谁"。

## 关键事实：在模型眼里，预设和角色卡是同一段文字

这是最多人没想通的一点。

ST 每次对话，会把预设的所有开启块 + 角色卡内容 + 世界书命中条目，**拼接成一段完整的提示词**发给模型。模型看到的只有一个 system 消息 + 对话历史。它**分不清**哪段文字来自预设、哪段来自卡：

```text
模型实际看到的（示意）：
┌──────────────────────────────────┐
│ 你在进行沉浸式中文角色扮演……       │ ← 预设的破限块写的
│ 你是场景中的NPC，不替玩家行动……    │ ← 预设的抢话块写的
│ 情感只能通过外在呈现……            │ ← 预设的文风块写的
│ ─────────────────────────────── │
│ # 角色：林雪，24岁插画师……        │ ← 角色卡写的
└──────────────────────────────────┘
        对模型 = 同一段系统提示词
```

**"规则必须写在预设里"只是一种习惯，不是一种必然。** 模型根本不在乎规则住在哪。

## 看看预设级写法长什么样

狐神抚的模块内容，每一段都是教科书级的系统提示写法。随便摘两段：

**「禁止抢话」块**——目标、规则、范围、停止条件，四段式清清楚楚：

```markdown
## 抢话规则：禁止抢话
你是场景中的 NPC 和环境本身。你只做两件事：
按 NPC 自身的性格和动机主动行动，并描述你所看到的世界。

## 核心规则
1. 不替玩家行动或发言
   - 禁止以玩家角色为主语，描写其任何主动行为
   - 禁止替玩家角色说台词
   - 禁止推测或描写玩家角色的内心活动
2. 主动推进，不等指令
   - NPC 按照自己的性格、情绪和动机自由行动……

## 停止条件
- 向玩家提出了问题或给出了明确选项时，停止输出
```

**「防全知」块**——把"别剧透"这种模糊要求拆成可执行的感官规则：

```markdown
## 感官边界
你只能书写角色此刻直接感知到的一切。
- 视觉：只写双眼所见。门后的景象，在推开门之前，只是未知
- 听觉：只写双耳所闻。隔壁的对话，在你贴耳倾听之前，只是模糊声响
- 内在感知：他人的心思，对方说出口了，你才知道

## 认知边界
- 身份限定：角色的身份职业阶层，划定其知识疆域
- 时代限定：古代将军会说筋骨与气力，不说肌肉与营养
- 各人活在各人的知识里，不跨域，不越界，不读心
```

注意这些写法的共同点：**没有一句是"内容"，全是"规则"**——不描述角色穿什么衣服，只约束模型该怎么写。这就是系统提示工程。

## 现状批判：预设兜底养出的破烂卡

现在社区大部分角色卡什么样？

```text
description: 散文式人设小传，想到哪写到哪
personality: 几个标签
first_mes: 还行
mes_example: 空的
格式控制 / 防抢戏 / 节奏 / 输出结构：全都没有
```

**全靠预设兜底。** 所以同一张卡，配狐神抚这种神预设就是神卡，配默认预设就是人工智障——评论区两极分化的根源不是卡忽神忽鬼，是**每个人的预设不同，而卡自己没有站稳的能力**。

卡作者把系统提示工程的责任外包给了预设作者。然后两边互相甩锅。

## 自足卡：把预设级写法搬进卡里

既然模型分不清规则住在哪，正确的做法就是——**角色卡自己带齐运行规则**。把狐神抚那种模块写法，按你这张卡的需要裁剪后写进 description：

```markdown
# 运行时契约
你在进行文字角色扮演，扮演 {{char}}，用户扮演 {{user}}。
- 只写 {{char}} 的动作、语言；永远不代替 {{user}} 发言或做决定
- 回复 200~400 字，节奏比文采重要

# 叙事规则
- 你只能写 {{char}} 此刻直接感知到的：门后的景象在推开门之前是未知
- {{char}} 的情绪只通过身体呈现：不直接写"她难过"，写"她把杯子端起来，又原样放了回去"
- {{user}} 的内心活动禁止推测

# 角色：林雪
24 岁自由插画师，住 {{user}} 隔壁。银长发，黑眼圈，家里有只橘猫叫"年糕"。

# 性格与行为
- 表面温柔，熟了毒舌，毒舌精准但不带恶意
- 关心的方式是行动不是语言：嘴上嫌弃，手里帮忙

# 输出格式
*动作用星号包裹*
"台词用引号"
```

看出来了吗——**这就是一份完整的系统提示，只是它住在角色卡里**。运行时契约、防抢话、防全知、文风要求，这些狐神抚模块里的规则，裁剪成这张卡需要的尺寸，直接写进来。

## 自足卡的好处与注意

**好处：**
1. 不挑预设——空预设都跑得稳，规则是卡自带的
2. 分享不翻车——别人的体验和你调试时一致，不用写"建议搭配XX预设"
3. 行为可预期——格式、节奏、禁区全部自己定义

**注意：**
- 配"干净"预设用。预设里重复的格式规则（字数、文风）关掉，避免指令打架
- 规则照抄不行——**按这张卡的需要裁剪**。狐神抚 62 个块是自助餐，不是全都要
- token 预算纪律不变（第 06 篇）：规则部分 ≤300 token，够用
- 预设仍有卡管不了的部分：采样参数、世界书注入策略、组装顺序——别走极端说预设没用

## 小结

- 预设 = 可开关的系统提示模块库 + 组装顺序 + 注入位置 + 采样参数
- 模型眼里预设和卡是同一段提示词——规则住哪都行
- 预设级写法 = 全是规则没有内容；破烂卡 = 全是内容没有规则
- 自足卡：把这张卡需要的规则裁剪后写进卡里，插进任何环境都能站稳
