# 实战篇 02｜世界书：装不下的资料，搬出去

> 「提示词补完计划·实战篇」第二篇。
> 01 把单角色卡写对了，但收尾时留了一个硬边界：
> **单角色卡只装得下一份压缩过的背景。**
> 这一篇讲怎么把装不下的资料搬出去——搬进世界书。

---

## 〇、什么时候该搬

三个信号，出现一个就该建世界书了：

1. **卡变胖了。** 角色档案里的世界设定比角色本身还多，模型翻半天找不到"她是谁"
2. **有些资料只有聊到才需要。** 三色团子、八重堂、眼狩令——
   它们重要，但不值得每轮都占着上下文的位置
3. **背景开始重复。** 你在卡里、开场白里、示例里反复交代同一批世界信息
   （复习 01 的引用纪律：同一信息只在一处写死）

搬家的方向只有一个：**卡里放"她是谁"，书里放"这个世界什么样"。**

⚠️ 先钉死现阶段的前提：这还是**单角色卡**的世界——
**LLM 只扮演一个角色**（她）。世界书里的一切，
是她生活、走动、提及的世界；书中出现的人物，
只是模型顺带呈现的背景角色，不是另一张卡。

---

## 一、先建立一个认知：世界书是变量的仓库

01 里我们说过：写卡像写程序，主程序开头定义变量，全文引用。

世界书就是这个模型的下一步——**变量太多，主程序装不下了，
于是有了外部存储，按需加载。**

- 卡 = 主程序（常驻内存，每轮都在）
- 世界书条目 = 外部文件（**提到才加载，不提不占 token**）
- 关键词 = 文件名/函数名——对话里一说这个词，对应条目立刻被调进上下文

所以世界书不是设定集。设定集是给人读的，世界书是给模型**查**的。
这个区别决定了后面每一条写法。

---

## 二、条目解剖：一个条目长什么样

世界书由条目组成。一个条目就三样东西：

```markdown
【条目】天守阁
关键词：天守阁,将军府
内容：稻妻城的权力中枢，雷电影的居所。最深处是她的静室，
空旷整洁，唯一的多余之物是矮桌上的甜点心碟子。
日常政务由人偶「将军」在此处理。
```

- **关键词**：条目的名字。对话里出现它，条目注入。
  ⚠️ 格式细节：**多个关键词之间用英文逗号 `,` 分隔**——
  不是中文顿号、不是空格，世界书的匹配机制认这个
- **内容**：被注入的资料本体
- **触发方式**：这条是"关键词触发"——还有另一种叫"常驻"，第五节讲

一句话总结用法：**对话是查询语句，关键词是索引，内容是查询结果。**
模型没看到条目时不知道它存在——所以条目写得多好不重要，
**触发得到**才重要。

---

## 三、系统提示怎么"引用"世界书

卡和世界书是分开的两份东西。它们怎么连起来？分两层看：

**第一层：机制绑定（软件管的事）**

- **角色书**：世界书内嵌在角色卡里，随卡导入导出，
  只在这张卡的聊天里生效——卡带到哪，世界跟到哪
- **全局世界书**：独立存在，所有聊天共享

（机制细节第一季 07 讲过，这里只讲用法。）

**第二层：提示词里的接引（你管的事）**

条目被关键词触发后，是**凭空出现**在上下文里的。
模型不知道它是哪来的、可不可信——所以卡里要给一句"接引"，
告诉模型怎么对待这些冒出来的资料。写进能力模块：

```markdown
- 对话中随时可能出现【世界资料】条目——那是世界书注入的设定。
  视为你早已知道的事实，直接使用，不解释来源
```

用 01 的编程模型说：**主程序不 import 具体条目——运行时动态链接。**
卡里只说"凡动态链接进来的世界资料，当作已知事实"。

> 反向纪律：卡里**不预告**具体条目的内容。
> 接引只说"会有资料来"，不说"资料是什么"——
> 把"八重神子是宫司"也写进卡，就回到重复定义了。

---

## 四、触发词设计：世界书用法的第一核心

条目再好，触发不到等于没写。触发词设计只有一条直觉：

> **用户和角色嘴里会说出来的词，才配当触发词。**

### 正例

```markdown
【条目】八重神子
关键词：八重神子,神子,宫司大人,八重堂
```

四个词各有来历：全名、昵称、敬称、以及她开的出版社
（聊到八重堂轻小说时，这条也该出来）。**别名要挂全。**

### 反例

```markdown
❌ 关键词：鸣神永恒守护者与八重宫司之契约
```

——没有任何人会在对话里说出这串字。这条目永远躺着。

```markdown
❌ 关键词：她
```

——太宽。每轮都触发，等于常驻，还污染所有对话。

### 宽度的手感

- **太窄**：生造词、官方全名、书面称谓 → 永远不触发
- **太宽**：代词、常用动词、世界观通用词（"神""力量"）→ 乱触发
- **刚好**：专有名词 + 它的所有口语变体

设计完自问一句：**"用户聊到这件事时，最可能打出哪个词？"**
那个词必须在关键词列表里。

---

## 五、常驻 vs 触发：世界书用法的第二核心

条目有两种活法：

| 类型 | 行为 | 该放什么 |
|:--|:--|:--|
| **常驻** | 每轮都注入，不需要关键词 | 世界铁律——无论聊到哪都必须成立的事 |
| **触发** | 关键词出现才注入 | 资料本体——聊到才需要的事 |

判断标准就一个问题：**"这件事，是不是无论话题走到哪都必须成立？"**

- 是 → 常驻（比如：这个世界没有魔法——一句话铁律）
- 否 → 触发（比如：金玫瑰酒馆的老板娘是退休刺客——只有去了酒馆才需要）

### 常驻陷阱

常驻条目的膨胀是世界书版的"倾倒数据"。
十条常驻 = 每轮白烧一千 token，还会稀释角色档案的注意力。

常驻条目的体量纪律：**能写一句不写两句。**
它不是资料库，是世界宪法——宪法都很短。

---

## 六、分层组织：说一个词，唤醒一座城

大世界不止一本平铺的账。条目之间可以**互相触发**：
A 条目的内容里提到了 B 的关键词，B 也被唤醒。

```markdown
【条目】鸣神大社
关键词：鸣神大社,大社,神樱
内容：稻妻的信仰中心，神樱树所在之地。宫司八重神子的居所，
与城中的天守阁遥遥相对。
```

用户只说"去鸣神大社"——这一条注入，内容里带的"八重神子"和"天守阁"
又唤醒了各自的条目。**一条词，拉起一张网。**

用这个机制组织大世界，分层从上到下：

```
世界规则（常驻·一句话铁律）
  → 地区（稻妻）
    → 地点（天守阁 / 鸣神大社 / 八重堂）
      → 人物（八重神子 / 九条裟罗）
      → 事件（眼狩令 / 锁国令）
```

**技巧：主动埋词。** 写条目内容时，有意把下层条目的关键词写进去
（"宫司八重神子的居所"），网就织起来了。

> ⚠️ 递归很香但会爆 token。链式触发一层拉一层，
> 一次注入几千 token 就喧宾夺主了。层级别超过三层，
> 每层条目内容别超过一小段。

---

## 七、卡和书的分工：灰色地带怎么判

大多数归属判断是容易的。难的是灰色地带，比如八重神子：
她是"世界的一部分"还是"一个角色"？

记住现阶段的前提——**LLM 只扮演一个角色**。所以判据只有一个：

**这个人需要被"演"吗？**

- 她 = 主角 → 在卡里，有完整的角色档案，模型全程以她的身份回应
- 其他所有人（哪怕是神子这样的重要人物）→ 在世界书里，
  是条目。模型按条目**顺带呈现**他们的言行，
  但他们不拥有卡，不是"被扮演"的对象

一张卡 + 一本书，就是"一个角色 + 一个世界"的完整形态。

## 八、完整示例：雷电影的稻妻世界书

接 01 的例子。雷电影的卡里只留"她是谁"，
稻妻的世界搬进这本小书——**先看完整成品，再听解读。**

<details>
<summary>展开：稻妻世界书（7 条）</summary>

```markdown
【条目 0 · 常驻】
内容：眼狩令与锁国令已废止。稻妻正在重新开国，
商路初通，民间对将军大人的敬畏未减，但街上已有外国货与笑声。

【条目 1】
关键词：天守阁,将军府
内容：稻妻城的权力中枢，雷电影的居所。最深处是她的静室，
空旷整洁，唯一的多余之物是矮桌上的甜点心碟子。
日常政务由人偶「将军」在此处理。

【条目 2】
关键词：一心净土,净土
内容：雷电影的内在精神空间。赤色鸟居立在无垠星空之下，
时间近乎静止。能进入这里的，只有她允许的人。

【条目 3】
关键词：鸣神大社,大社,神樱
内容：稻妻的信仰中心，神樱树所在之地，位于影向山巅。
宫司八重神子的居所，与城中的天守阁遥遥相对。

【条目 4】
关键词：八重神子,神子,宫司大人,八重堂
内容：鸣神大社的宫司，雷电影的眷属与挚友，活了几百年的狐仙。
表面慵懒恶趣味，以揭穿影的伪装为乐，实则一直替她守着稻妻。
经营八重堂出版社，给影寄轻小说。

【条目 5】
关键词：眼狩令,锁国令
内容：曾收缴全国神之眼、封锁国境的两道法令，
源于影对「永恒」的执念。现已废止——但被执行过的伤痕还在，
提起时老一辈会沉默。

【条目 6】
关键词：三色团子,团子,甜点心
内容：稻妻的常见点心，三串糯米团子插在小签上。
雷电影的最爱——她评价它的全部用词是：「甜的。」
```

</details>

### 解读：这本小书里的每个决定

1. **只有条目 0 是常驻。** 一句话铁律（时代背景），其余全部触发。
   世界宪法很短
2. **条目 4 挂了四个关键词**——全名/昵称/敬称/她开的店。
   用户怎么说都能触发到
3. **条目 3 的内容里埋了两个词**：「八重神子」「天守阁」。
   用户问神社，模型顺手"想起"宫司和将军府——递归网的实战样子
4. **条目 5 是历史，不是设定集条目**——它写了"现在还怎么影响人"
   （老一辈会沉默），资料要能变成戏
5. **条目 6 看起来琐碎，恰恰是世界书的精髓**：三色团子这种细节
   放卡里嫌挤，不放又可惜——聊到点心时才注入，刚刚好
6. **影本人的资料一条都没有。** 她在卡里。书里只有世界——
   这就是分工

## 九、可拆装视角：条目也是模块

复习 01 的第八节：模块可拆、可开关、可复用。世界书完全同构：

- **条目 = 模块**：每条独立，可单独开关——和卡里的模块同一套思维
- **一本书 = 一个世界的资料库**：这个世界的一切设定只在这一个地方存在，
  是引用纪律的终极形态
- **常驻条目 = 世界的主提示**：放铁律，越少越好

写卡的人攒模块，写世界的人攒条目——
到最后你会发现，它们是同一套积木。

## 十、常见翻车清单

| 翻车 | 根因 | 修法 |
|:--|:--|:--|
| 条目永远不触发 | 关键词是生造词/书面语 | 换成用户嘴里会说出的词，别名挂全 |
| 条目乱触发 | 关键词太宽（"她""神"） | 收窄到专有名词 |
| 模型只记得书不记得人 | 常驻太多，稀释了卡 | 常驻砍到一句话铁律 |
| 一次触发注入几千字 | 递归层级太深/条目太长 | 层级≤3，条目一小段 |
| 条目写得像百科 | 资料不能变成戏 | 每条多问一句"这会怎么影响现在" |
| 卡里书里各写一遍 | 违反引用纪律 | 世界是书的事，卡只写人 |

## 收尾：世界书速查表

| 件 | 一句话 |
|:--|:--|
| 条目 | 关键词 + 内容 + 触发方式 |
| 触发词 | 嘴里会说出来的词才配当，别名挂全 |
| 常驻 | 世界宪法，一句话铁律，越少越好 |
| 触发 | 资料本体，聊到才注入 |
| 分层 | 世界→地区→地点→人物→事件，主动埋词织网 |
| 分工 | 卡写人，书写世界；灰色地带问"还会出现吗/需要演吗" |

**世界书的全部心法其实就一句：它不是你写给世界的情书，
是你给模型装的索引。**
