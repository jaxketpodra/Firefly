## 世界书：按需提供的世界设定

角色卡解决"这个角色是谁"，世界书（World Info / Lorebook）解决"**这个世界是什么样的**"。

核心机制是**关键词触发**：条目平时不进提示词，对话里出现了关键词才被注入。这完美解决了上下文预算问题——100 个地点设定，只有被提到的那个才占 token。

```
条目：
关键词：金玫瑰酒馆
内容：金玫瑰酒馆是银区的地标，老板娘薇伊是退休刺客，酒量惊人。
```

玩家一说"去金玫瑰酒馆"，这条设定立刻出现在模型的上下文里。不说就不占地方。

## 递归扫描：说一个词，唤醒一座城

ST 的世界书支持递归：条目内容里包含的关键词可以继续触发其他条目。

```
一级：橡树城 → 内容里提到"银区""铁卫团"
二级：银区 → 内容里提到"金玫瑰酒馆"
三级：金玫瑰酒馆 → 内容里提到老板娘薇伊
```

玩家只说"橡树城"，模型瞬间"回忆"起整个城市结构、地标、关键 NPC——**一条词唤醒一张网**。设计大世界时，用这个层级组织设定：世界观 → 地区 → 势力 → 地点 → 人物。

> [!WARNING]
> 递归很香但会爆 token。给条目设好概率和预算上限，别让一次触发连锁注入几千 token。

## 世界书 vs 角色书

- **世界书（World Book）**：全局生效，不绑定角色，所有聊天共享
- **角色书（Character Book）**：内嵌在角色卡里，随卡导入导出，只在该角色的聊天里生效

做同人卡时把"原作设定"塞进角色书（卡带到哪设定跟到哪），做原创大世界时用全局世界书。两者可以叠加：角色书先注入，世界书用剩余空间。

## 同人卡：准确性与呼吸感

写同人角色（比如 EVA 的明日香）有两个雷区：

**雷区一：把维基百科抄进 description**。几千字的原作编年史只会稀释人设。只留"此刻有用的"：

```markdown
{{char}} 是惣流·明日香·兰格雷，EVA 二号机驾驶员。
骄傲、好胜、用攻击性掩饰脆弱。口头禅"あんたバカぁ？"
```

名场面和原作知识交给世界书（关键词"二号机""使徒"触发），需要时才注入。

**雷区二：只有原作没有"此刻"**。同人卡的价值是"这个角色在**你的**故事里"——scenario 里写清楚：时间点（原作前/中/后/平行世界）、与 {{user}} 的关系、二创的规则边界。

## 超多角色：群组与大世界

几十个角色同框的正确姿势：

1. **一个角色一张卡**——别把 5 个角色塞进一张卡，模型会人格串味
2. **群组聊天（Group Chat）**：ST 原生支持多角色同群，按规则轮流发言。配一个"导演"系统提示控制节奏
3. **NPC 进世界书**：路人级角色不值得一张卡，写成世界书条目（关键词触发），提到才出现
4. **模块化预设**：把规则拆成可开关的模块（文风、视角、节奏控制……），不同剧情阶段开不同组合——我们的 RP 引擎就是这么做的，14 组模块按需挂载

大世界的稳定性公式：**少量常驻（主角卡）+ 按需注入（世界书）+ 状态外化（每轮更新的世界状态）**。

## 小结

- 世界书 = 关键词触发的动态设定库
- 递归扫描让设定连成网
- 同人卡：人设精简常驻，原作知识进世界书
- 多角色：一人一张卡 + 世界书管 NPC + 模块化预设控节奏
