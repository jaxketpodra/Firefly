## 角色卡是什么

一张 ST 角色卡（PNG 内嵌 JSON 或纯 JSON）本质是一份**每轮对话都会发给模型的常驻提示词**。卡写得好不好，直接决定角色稳不稳。

Character Card V2 规范的核心字段：

```
name            角色名
description     角色描述（核心中的核心）
personality     性格摘要
scenario        场景设定
first_mes       开场白
mes_example     示例对话
creator_notes   给使用者看的备注（不进提示词）
character_book  内嵌世界书（下一篇讲）
```

## description：角色的"真理"

这里写的是**永远成立**的事实：外貌、身份、经历、关系起点。

写法要点：

```markdown
{{char}} 是 24 岁的自由插画师，住在 {{user}} 隔壁。
银色长发，赶稿时随便扎起来。黑眼圈常年挂脸上，但笑起来眼睛会弯。
家里养了一只叫"年糕"的橘猫。
```

- 第三人称平铺直叙，别写成诗
- 一句话一个信息点
- **只写静态事实**，心情和状态别写进来（那是动态注入的活儿）

预算：≤200 token。见过太多卡在这里写 2000 字人物小传——模型看完反而抓不住重点。

## personality：一句话性格

很多人会在这里写一大段，其实它是给模型做"快速索引"的：

```
温柔但有距离感，毒舌时精准戳人痛处，赶稿期暴躁，对猫没有抵抗力。
```

逗号分隔的短语串就行。详细信息应该在 description 里，这里只是标签。

## scenario：此刻的舞台

```
时间是夏末，{{user}} 刚搬到这栋公寓一周。{{char}} 正在赶一个周五截止的商稿，已经两天没出门了。
```

写**剧情开始时的状态**——时间、地点、双方关系现状。给 first_mes 提供发生的土壤。

## first_mes：全卡最重要的一段

开场白是模型的**风格锚点**——它会拿第一段当范文模仿整场对话的格式、语气、详略。

所以 first_mes 必须：

1. **亲自展示你想要的回复格式**（动作怎么写、对话怎么写、要不要状态栏）
2. 定好双方关系的起点张力
3. 长度 = 你期望的平均回复长度（写 3000 字开场，它以后就回 3000 字）

```
*楼道里传来塑料袋的窸窣声。林雪拎着便利店的袋子站在门口，头发乱糟糟的，看到你时明显愣了一下。*

"……新搬来的？" *她目光在你和 502 的门牌之间扫了个来回，* "我是隔壁的林雪。那个，借个酱油可以吗？我的用完了，外卖还没……" 

*话说到一半她自己先放弃了，摆摆手，* "算了当我没问，你继续搬。"

*但她没有走。*
```

动作描写用 *星号* 还是别的格式无所谓——**重要的是你写了什么格式，模型就用什么格式**。

## mes_example：放格式，不放剧情

```
<START>
{{user}}: 酱油给你。
{{char}}: *她接过瓶子时指尖擦过你的手背，凉得像没晒过太阳。* "谢了。改天……改天请你吃我做的饭抵债。" *她说完自己先皱了皱眉，像是不习惯说这种话。*
```

- 用 `<START>` 分隔多组示例
- 每组都展示"动作+台词+细节"的标准结构
- **示例里永远别让 {{char}} 替 {{user}} 说话**（防抢戏，第 04 篇讲过）
- 2~3 组足够，多了浪费 token

## 常见翻车清单

| 翻车 | 原因 | 解法 |
|:---|:---|:---|
| 角色 OOC 成万能温柔姐姐 | description 写了"温柔"但没写"距离感" | 性格写矛盾面，人才立体 |
| 模型操控我的角色 | mes_example 里 {{char}} 代打了 {{user}} | 示例严格只写自己的部分 |
| 性别推断错误 | 卡里写死了"哥哥/弟弟" | 指代一律 `{{user}}` |
| 回复越来越短 | first_mes 太短，或示例太简 | 开场白写足分量 |
| 设定被遗忘 | 关键设定埋在长文中间 | 精简+前置，参见第 02 篇 |

## 小结

- description 写真理，personality 写标签，scenario 写此刻
- first_mes 是风格锚点，值得花一半精力打磨
- mes_example 展示格式而非剧情
- 全卡 ≤1500 token
